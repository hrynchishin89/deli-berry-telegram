# Deli Berry Production 1.0 — установка без промежуточных патчей

Это единый финальный релиз. Старые архивы V7, V8, V8.1, V8.2 и отдельные патчи больше не устанавливайте.

## Что получится после установки

- отдельное меню ТЦ Discovery / Дыбенко и ТРЦ Зеленопарк;
- кофе и листовой чай только в Зеленопарке;
- объёмы, цены и обязательные вкусы/опции в одной карточке;
- Telegram-заказы в группу менеджеров;
- статусы: Новый → Подтверждён → Оплачен → Готовится → Заказ готов → В доставке → Завершён;
- ответ менеджера клиенту, ссылка и локальный QR на оплату;
- ID клиентов вида `DB-000001`;
- накопительные бонусы 5%, списание до 30%, 1 бонус = 1 ₽;
- профиль, история заказов и повтор заказа;
- админки заказов, каталога и бонусов;
- постоянное хранение заказов и бонусов в PostgreSQL;
- строгая проверка Telegram-сессии и защита от частого спама заявками.

# Этап 1. Подготовить безопасное обновление GitHub

В финальном проекте 145 файлов. Через браузер GitHub за один раз можно загрузить не больше 100 файлов, поэтому загрузка делается **двумя частями**. Это одна версия приложения, а не два разных патча.

## 1. Скачайте резервную копию текущего GitHub

1. Откройте репозиторий `deli-berry-telegram`.
2. Нажмите зелёную кнопку **Code**.
3. Нажмите **Download ZIP**.
4. Сохраните архив на компьютер.

## 2. Временно выключите автоматический деплой Render

Это нужно, чтобы Render не начал запуск после первой половины файлов.

1. Откройте Render → сервис `deli-berry-telegram`.
2. Слева нажмите **Settings**.
3. Найдите **Auto-Deploy** или **Auto-Deploy Trigger**.
4. Выберите **Off / No** и сохраните.

Не удаляйте сервис и не меняйте токен.

## 3. Загрузите часть 1 — `webapp`

1. Распакуйте архив `DELI_BERRY_PRODUCTION_1_0_UPLOAD_PART_1_WEBAPP.zip`.
2. Откройте GitHub → корень репозитория, где виден `package.json`.
3. Нажмите **Add file → Upload files**.
4. Перетащите папку `webapp` из распакованной части 1.
5. Дождитесь окончания загрузки.
6. В комментарии напишите:

```text
Deli Berry Production 1.0 part 1 of 2
```

7. Нажмите **Commit changes**.

## 4. Загрузите часть 2 — backend и данные

1. Распакуйте `DELI_BERRY_PRODUCTION_1_0_UPLOAD_PART_2_BACKEND.zip`.
2. В GitHub снова откройте корень репозитория.
3. Нажмите **Add file → Upload files**.
4. Откройте распакованную папку части 2, нажмите `Ctrl+A` и перетащите **всё содержимое** на GitHub.
5. Дождитесь окончания загрузки.
6. В комментарии напишите:

```text
Deli Berry Production 1.0 part 2 of 2
```

7. Нажмите **Commit changes**.

## 5. Проверьте корень репозитория

На главной странице должны находиться:

```text
package.json
Dockerfile
src
data
webapp
docs
database
scripts
```

Не должно появиться лишней внешней папки `DELI_BERRY_PRODUCTION_1_0...`.

# Этап 2. Создать постоянную базу Render Postgres

Бонусы, ID клиентов, заказы и статусы нельзя хранить только в локальных JSON-файлах Render.

1. Render Dashboard → **New → Postgres**.
2. Name:

```text
deli-berry-db
```

3. Region — **тот же**, что у web service `deli-berry-telegram`.
4. Для реального запуска выберите платный план базы. Бесплатная база подходит только для короткой проверки.
5. Нажмите **Create Database**.
6. Дождитесь статуса **Available**.
7. Нажмите **Connect**.
8. Скопируйте **Internal Database URL**.

Таблицы приложение создаст само при первом запуске. Файл `database/schema.sql` приложен для проверки.

# Этап 3. Настроить Web Service Render

## 1. Выберите стабильный тариф web service

Для реальных заказов выберите **Starter или выше**. Бесплатный web service может засыпать, поэтому ответы менеджера и кнопки статусов могут срабатывать с задержкой.

## 2. Заполните Environment Variables

Render → `deli-berry-telegram` → **Environment → Edit**.

Сохраните свои текущие секреты и добавьте/проверьте:

```env
BUSINESS_NAME=Deli Berry
BOT_TOKEN=ВАШ_АКТУАЛЬНЫЙ_ТОКЕН
WEBAPP_URL=https://deli-berry-telegram.onrender.com
PUBLIC_URL=https://deli-berry-telegram.onrender.com
MANAGER_CHAT_ID=-100XXXXXXXXXX
ADMIN_PIN=ПРИДУМАЙТЕ_ДЛИННЫЙ_СЕКРЕТНЫЙ_PIN

REQUIRE_TELEGRAM_AUTH=true
TELEGRAM_AUTH_MAX_AGE_SECONDS=86400

DATABASE_URL=ВСТАВЬТЕ_INTERNAL_DATABASE_URL
DATABASE_SSL=true

BONUS_ENABLED=true
BONUS_EARN_PERCENT=5
BONUS_MAX_REDEEM_PERCENT=30
BONUS_RUBLES_PER_POINT=1

ORDER_RATE_LIMIT_WINDOW_MS=60000
ORDER_RATE_LIMIT_MAX=8
PROFILE_RATE_LIMIT_MAX=60

SETUP_TELEGRAM_ON_START=true
NODE_ENV=production
```

Не присылайте `BOT_TOKEN`, `ADMIN_PIN` и `DATABASE_URL` в чат и не добавляйте их в GitHub.

Нажмите **Save Changes**. Если Render предложит сразу deploy, можно подтвердить после завершения обоих GitHub-коммитов.

## 3. Каталог-админка с сохранением фото — опционально

Для сохранения фото и каталога из админки в GitHub создайте fine-grained token только для репозитория `deli-berry-telegram` с правом **Contents: Read and write** и добавьте:

```env
GITHUB_OWNER=hrynchishin89
GITHUB_REPO=deli-berry-telegram
GITHUB_BRANCH=main
GITHUB_TOKEN=СЕКРЕТНЫЙ_GITHUB_TOKEN
```

Без GitHub token админка каталога открывается, но загруженные локально файлы не считаются постоянным хранилищем.

# Этап 4. Запустить только последний полный коммит

1. Render → **Events**.
2. Нажмите **Manual Deploy → Deploy latest commit**.
3. Дождитесь:

```text
Build successful
Deploy live
```

4. После успешного запуска можно вернуть **Settings → Auto-Deploy → On**, чтобы будущие целостные коммиты запускались автоматически.

# Этап 5. Проверить здоровье приложения

Откройте:

```text
https://deli-berry-telegram.onrender.com/api/health
```

Для боевого запуска должно быть:

```json
{
  "ok": true,
  "readiness": {
    "botToken": true,
    "webAppUrl": true,
    "managerChatId": true,
    "database": "postgres",
    "persistentDatabase": true,
    "bonusEnabled": true,
    "telegramAuthRequired": true
  }
}
```

Если `database` равно `json` или `persistentDatabase` равно `false`, не запускайте бонусы для клиентов: проверьте `DATABASE_URL`.

# Этап 6. Настроить Telegram

Автонастройка включена. Для ручного запуска откройте:

```text
https://deli-berry-telegram.onrender.com/setup.html
```

1. Введите `ADMIN_PIN`.
2. Нажмите **Настроить Telegram**.
3. Закройте Mini App.
4. В чате с ботом отправьте `/start`.
5. Нажмите **Заказать 🍓**.

Команды группы менеджеров:

```text
/manager
/groupid
/today
/export
/pay НОМЕР_ЗАКАЗА ССЫЛКА
/qr НОМЕР_ЗАКАЗА ССЫЛКА
/reply НОМЕР_ЗАКАЗА ТЕКСТ
```

# Этап 7. Проверить меню точек

## Дыбенко / ТЦ Discovery

- кофе отсутствует;
- листовой чай отсутствует;
- доступны напитки, милкшейки, смузи, фреши, добавки;
- старые дубли напитков скрыты.

## Зеленопарк

- кофе и чай;
- авторский кофе и айс-кофе;
- милкшейки;
- лимонады и мохито;
- bubble drinks;
- фреши;
- смузи;
- добавки.

## Обязательные варианты

1. Выберите объём — цена должна измениться.
2. Для милкшейка обязательно выберите вкус.
3. Для некоторых шоколадных напитков выберите тип шоколада.
4. В корзине должно отображаться, например:

```text
Молочный коктейль · 400 мл · Клубника
```

# Этап 8. Проверить заказ, статусы и бонусы

## Первый заказ

1. Добавьте товар с объёмом и вкусом.
2. Оформите заказ с комментарием:

```text
ТЕСТ — НЕ ГОТОВИТЬ
```

3. В группе менеджеров нажмите **Подтвердить**.
4. Нажмите **Оплачен**.
5. Нажмите **Готовится** или сразу **Заказ готов** после подтверждения.
6. Нажмите **Завершён**.

Клиент должен получить ID вида `DB-000001`. После завершения начисляется 5% от суммы товаров.

## Второй заказ

1. Откройте **Профиль**.
2. Проверьте бонусный баланс и историю.
3. Сделайте второй заказ.
4. В корзине включите списание бонусов.
5. Списание должно быть не больше 30% стоимости товаров.
6. Отмените один тестовый заказ и убедитесь, что зарезервированные бонусы вернулись.

# Если возникла ошибка

- **Render Failed:** откройте Logs и пришлите последние красные строки.
- **Старый интерфейс:** закройте Mini App, полностью перезапустите Telegram и снова `/start`.
- **База работает как JSON:** проверьте `DATABASE_URL`, `DATABASE_SSL` и одинаковый регион сервиса и БД.
- **Заказ не приходит:** проверьте `MANAGER_CHAT_ID` и наличие бота в группе.
- **401 Telegram session:** закройте приложение и откройте его заново именно из Telegram-бота.
- **Нужно вернуться назад:** Render → Events → предыдущий успешный deploy → Rollback.
