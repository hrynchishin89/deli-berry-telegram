# Дели Берри · отчёт проверки Cloudflare Free

Дата: 29.09.2026. Статус: код готов к проверке в аккаунте владельца; публичного deployment пока нет. Боевые Telegram/Яндекс Пэй выключены.

## Выполнено

- `npm run check` — успешно: контроль исходного каталога/цен/клиентского дизайна, 19/19 тестов, Wrangler dry-run.
- D1 миграции выполнены в локальном workerd; отдельный тестовый D1 каждый раз создаётся с нуля и применяет все три SQL-файла, включая триггеры и FOREIGN KEY.
- Native workerd fetch: health, config, запрет гостя/чужого оператора, Origin, неверный JSON, тело >64 KiB.
- Web Crypto HMAC Telegram: подлинность, подмена, повтор поля, auth_date в прошлом/будущем, недопустимый ID.
- Web Crypto ES256 Яндекс: подпись, истёкший header, неверный alg/merchant, подмена payload.
- D1: конкурентные create, UNIQUE(user_id,request_key), конфликт состава, изоляция заказов, CAS двух операторских действий, полный rollback, отсутствие потерянного журнала/ложного outbox.
- Платёж: только после подтверждения, один payment/order и request_id; sync-payment не создаёт PAID. Прямой UPDATE PAID блокируется триггером.
- Проверенный webhook: amount/orderId/merchantId/currency; сохранение доказательства; повтор события; запрет понижения CAPTURED/REFUNDED; частичный/полный возврат.
- Самовывоз, курьер, подготовка, сроки годности/хранения, стоп-листы по точкам, аудит настроек.
- Telegram webhook: secret_token, dedupe update_id. Outbox: ошибки, повтор, две конкурентные lease без повторного захвата одной записи.
- Пагинация заказов при одинаковом created_at без пропусков; полный журнал страницами по 50 записей.
- Клиент: сумма с сервера, 15-минутные слоты, ошибка POST не создаёт фиктивного заказа, неизменный ключ повторной отправки, XSS escaping, отсутствие ручного PAID.

Максимум в измеренных сервисных сценариях: **17 D1 statements**. В HTTP добавляются максимум 3 rate-limit statements; внутренний защитный бюджет — 45, лимит Free — 50. Статические файлы обходят Worker. Криптография использует только Web Crypto; код не импортирует node:*, pg, jose, Express/ORM.

Wrangler dry-run: **84.83 KiB**, gzip **18.74 KiB**, 29 assets. Нет runtime npm dependencies. Локальная длительность всего набора ~7.4 s — это wall time тестов, НЕ CPU одного Worker request.

Каталог (9 семейств/16 вариантов), клиентские HTML/app.js/CSS и изображения совпадают с сохранённой 1.1.1 побайтово по SHA-256. В operator.js изменена только загрузка полного журнала по страницам; внешний вид не изменён.

## Не подтверждено — обязательные оставшиеся проверки

1. Облачный deployment: Cloudflare dashboard оставил этот браузер на Performing security verification после одной повторной загрузки. Авторизованного Wrangler/API token нет. URL не выдуман, платные тарифы/карта/домен не подключались.
2. CPU ≤10 ms для каждого маршрута: требует Workers Observability на фактическом Free deployment, включая ES256 на холодном/прогретом JWKS, create/confirm/payment/webhook/list/history/Cron. Локальные тесты и маленький bundle этого НЕ доказывают.
3. Визуальный браузерный прогон 360/390/430 px: не выполнен. Cloud browser запретил открытие локального file:// fixture, а публичный Worker пока недоступен. CSS/markup byte equality не заменяет визуальную приёмку. После deployment проверить все клиентские экраны и кабинет на каждой ширине и сохранить screenshots.
4. Боевой Telegram, реальный sandbox Яндекс Пэй, чеки/возврат, перенос старых данных — нужны секреты и отдельные подтверждения владельца. В тестах внешние платежи/доставка сообщений замоканы, криптографические подписи настоящие с тестовыми ключами.

На Supabase fallback не переключались: доказанного превышения CPU нет. Render не подключался. Free при превышении квот ограничивает работу вместо создания платного перерасхода. Регулярная инфраструктура выбранной схемы — $0, при условии сохранения тарифа Free.
