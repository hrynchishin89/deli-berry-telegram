# «Дели Берри» — сборка Mini App 1.1.1

Подготовлена 29.09.2026 для существующего сервиса Render `deli-berry-telegram`.
Это пакет исходников, тестов и реальных фотографий; `node_modules`, база и секреты в него не входят.
Исходная рабочая версия репозитория сохранена. Само добавление этих файлов не переключает приложение.

## Что включено

- Утверждённые 9 семейств / 16 вариантов, цены, фотографии, русский бренд.
- Бейдж «Ассорти · клубника + банан», интервалы по 15 минут.
- PostgreSQL, серверная проверка Telegram, один оператор, статусы и стоп-лист.
- Защита повторных заявок, очередь уведомлений и проверка платёжных уведомлений.
- Совместимость с существующей переменной Render `BOT_TOKEN`: секрет не требуется копировать.

27 локальных проверок прошли. В тестах используются PGlite и подменённые ответы Telegram/Яндекс Пэй.
Реальная оплата, мобильная визуальная проверка, внешняя PostgreSQL и Docker-сборка ещё не проверены.

## Воспроизведение

```sh
mkdir -p unpacked
tar -xzf deli-berry-miniapp-1.1.1.tar.gz -C unpacked
cd unpacked/source
npm ci
npm run check:all
```

Все редактируемые исходники находятся в `source/`, эталон каталога — в `data/catalog.json`.

## Переключение Render

До перезапуска действующего сервиса нужно сохранить его рабочие заказы и настройки.
Старая версия без `DATABASE_URL` использует временные JSON-файлы: код из GitHub не является копией живых данных.
CSV из существующего `/export` сохраняет основные поля заказов, но не полную историю и настройки.
Для полного сохранения нужен экспорт каталога `data/` из работающего контейнера.
Нельзя заменять эту проверку предположением, что заказов нет.

После сохранения данных и готовности окружения:

1. Подключить отдельную постоянную PostgreSQL в том же регионе и задать `DATABASE_URL` через защищённые настройки Render.
2. Оставить `BOT_TOKEN`; задать подтверждённые `OPERATOR_TELEGRAM_ID` и `TELEGRAM_BOT_ID`.
   `MANAGER_CHAT_ID` старой версии может быть группой: автоматически выдавать ему операторский доступ нельзя.
3. Установить случайный `TELEGRAM_WEBHOOK_SECRET` (32–256 символов из A–Z, a–z, 0–9, `_`, `-`).
4. Утвердить и разместить условия и политику; заполнить `TERMS_URL`, `PRIVACY_URL`, `LEGAL_VERSION`, затем `LEGAL_APPROVED=true`.
   Эти флаги нельзя выставлять для обхода проверки. `source/public/legal.html` остаётся черновиком.
5. Оставить `PAYMENT_MODE=disabled` до подключения и проверки sandbox Яндекс Пэй.
6. В Render выбрать эту ветку, Dockerfile Path `./Dockerfile.miniapp`, Build Context `.`, Health Check Path `/api/health`.
   `APP_ORIGIN` можно задать явно; иначе используется `RENDER_EXTERNAL_URL`.
7. Выполнить развёртывание и проверить HTTP health/catalog. На Render Free постоянного диска нет; заменять PostgreSQL на локальные файлы нельзя.
8. После успешного запуска выполнить из `/app/source`:

```sh
node scripts/configure-telegram.mjs
node scripts/configure-telegram.mjs --apply
```

Второй вызов меняет имя, меню и webhook существующего бота после проверки Bot ID и HTTPS health.
До него сохранить настройки предыдущего webhook. Неполученные обновления не удаляются.
Затем проверить вход покупателя и оператора, тестовый заказ, уведомления и внешний платёжный sandbox.
