# Подключение Telegram-каталога v5

## Что меняется

Корень действующего Node.js-сайта показывает каталог «Дели Берри» по таблице v5. Существующий бот, `BOT_TOKEN`, `MANAGER_CHAT_ID`, `WEBAPP_URL`, настройки и административные страницы остаются в том же проекте. Дополнительный бот, токен или хостинг не требуются. Новые публикации в Telegram/VK/MAX не создаются; файлы и триггеры VK не изменены.

Клиент оформляет самовывоз в Discovery или Зеленопарке с желаемыми датой и временем. Сервер проверяет подпись Telegram и пересчитывает сумму по общим правилам. Менеджер получает состав заявки и кнопки статуса; интерфейс подтверждает передачу только после успешного ответа Telegram. Оплата в приложении отсутствует.

## Размещение

1. Перед переносом в рабочую ветку сохранить текущие заказы/клиентов и настройки штатным способом хостинга. Секреты не включать в архив кода.
2. Проверить, что Render связан именно с этим репозиторием и рабочей веткой, и что `WEBAPP_URL` указывает на корень этого сервиса или `/index.html`. Существующие build/start команды `npm ci --omit=dev` / `npm start` подходят: готовая браузерная сборка включена в коммит.
3. Перенести проверенную ветку в рабочую и дождаться успешного развёртывания. Если автодеплой выключен, выполнить Deploy latest commit на существующем сервисе. Не создавать второй экземпляр бота.
4. Проверить `/api/health`: `catalogVersion` должен быть `v5-2026-09-28`. Проверить публичный корень, 13 фотографий, `/admin.html`, `/setup.html`. Результат POST `/api/catalog-v5/orders` без `initData` — HTTP 401, независимо от старой настройки `REQUIRE_TELEGRAM_AUTH`.
5. Открыть бот кнопкой меню или `/catalog` и сделать один явно помеченный тестовый заказ владельцем: выбранная сумма, точка/дата/время, получение менеджером, номер в Mini App. Тестовый заказ не оплачивать; отменить кнопкой статуса после проверки.

Текущий этап разработки не запускал заказ в живом Telegram и не раскрывал токены. При размещении отдельно подтвердить доступный публичный адрес и аккаунт бота — успешной сборки кода для этого недостаточно.

## Хранение и ограничения

- На 01.10.2026 публичная диагностика существующего сервера сообщала `database: json`, `persistentDatabase: false`. Такое хранилище может потерять историю/настройки при перезапуске или развёртывании. До рабочего запуска нужен постоянный диск для данных либо настроенный существующий Postgres через `DATABASE_URL`. Доставленные заявки остаются в чате менеджера, но это не заменяет сохранение базы.
- Новый маршрут проверяет Telegram всегда. Старые маршруты используют прежнюю настройку: диагностика сообщала `telegramAuthRequired: false`. Для всего сервиса следует включить `REQUIRE_TELEGRAM_AUTH=true`; эта переменная не извлекается и не меняется из каталога.
- Сохранённые заявки получают постоянный номер, повтор с тем же содержимым не создаёт вторую запись. При подтверждённой доставке повтор не отправляет новое сообщение. При частичной доставке возобновляется отправка после сохранённых частей.
- Нужен один работающий экземпляр сервера/бота, как и в текущем проекте. Если Telegram принял сообщение, но ответ или запись в хранилище потерялись, при повторе возможен дубль с тем же номером. Менеджер сверяет номер перед обработкой. Гарантия exactly-once не заявляется.
- Дата и время валидируются по Москве. Повтор заявки после уже наступившего желаемого времени требует сформировать новую актуальную заявку.
- Каталог использует утверждённые фотографии без изменения. Снимки сублимированной линии отмечены как примеры свежей линии. Актуального фото крафтовой коробки на 25 ягод нет — оставлена типографическая карточка.

## Проверки и откат

```sh
npm ci
npm --prefix miniapp ci
npm run catalog:test
npm run check
npm run catalog:build
```

Исходный `npm run test:production` до изменений уже падал с `Нет милкшейка с объёмами`. Он проверяет старый каталог напитков; этот тест и старые данные не переписывались, чтобы не скрывать исходный дефект. Новая интеграция проверяется отдельным `catalog:test`.

Сборка, TypeScript и тесты заявок не заменяют окончательную проверку интерфейса и отправки внутри настоящего Telegram. В текущей среде локальный Chromium отсутствует; нового браузерного прогона после подключения HTTP не было.

Откат интерфейса и сервера: вернуть коммит развёртывания к предыдущему проверенному SHA через штатный Render rollback. Не откатывать данные клиентов и заказов вместе с кодом. Схема базы не меняется; уже созданные v5-заявки используют существующую модель заказа.
